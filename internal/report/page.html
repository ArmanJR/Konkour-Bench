02

Performance, with uncertainty

Equal question weights. Only complete configurations receive a score and rank.

Display filters affect performance and resource views only. Frontiers always use all configurations in the analysis scope.

Intervals illustrate uncertainty under independent question sampling, not run-to-run model variance. This exam is not a random sample; shared topics and model errors can violate that assumption. Overlapping intervals are not a paired significance test.

Each resample draws the selected questions with replacement and keeps every configuration's answers paired, so a resample that repeats a hard question repeats it for all configurations. This is the paired comparison the intervals above cannot make. Ranks use competition ranking, so ties share the better rank. Like the Wilson intervals, it treats the exam's questions as exchangeable and does not measure run-to-run variation.

Unresolved answers

Unresolved requests, mostly timeouts, leave a configuration unranked. If they fall on harder questions than the configuration completed, its accuracy on completed answers overstates it. The Rasch estimate fits item difficulty to the complete-configuration panel, fits the configuration's ability to its completed answers, and adds the expected correct answers on the unresolved questions (± one standard deviation, ignoring uncertainty in ability). The held-out check refits the same model for each complete configuration on the same unresolved questions, where true answers are known. Same-model results on those questions show whether they are specifically hard for this model. Configurations with skipped or unsupported answers are not estimated.

Unranked configurations

Bounds assume every unresolved answer is wrong or correct. They are not confidence intervals. Unsupported tiers and image skips have no score bounds.

03

What does more reasoning buy?

Track answers gained and lost on the same questions, alongside the resource multiplier.

Requested tiers may map to different sent values. They are not equal internal thinking budgets across models.

A gain changes a wrong answer to correct; a regression does the reverse. Partial pairs compare only questions completed at both tiers and may be biased by missing difficult questions. Cost and token ratios use that same paired subset. No resampling or causal claim is implied.

05

The price of an answer

Compare measured resources at equal scope. Accuracy is not the only constraint.

Colored markers and the connected line mark the Pareto frontier: no other complete configuration is at least as accurate and uses no more of that resource, with one strict improvement. Frontier points are labeled directly with model name, effort, and accuracy; gray markers show the remaining configurations. Circle = minimal, square = medium, diamond = max. Hover or focus any point for details. Unknown accounting is excluded. Zero-cost points are listed in the table rather than on a log axis.

Medians and p90s summarize completed answers with known measurements; the table reports the sample count. Latency is original inference wall time, including CLI overhead, excluding queue time and earlier retries. It is not controlled for provider load. Native tokenizers and the Claude CLI protocol differ. Reasoning is already included in completion tokens; it is never added again.

Output tokens are completion tokens, including reasoning. The within-question ratio comes from a regression of log output tokens on a wrong-answer indicator with question and configuration fixed effects. It compares answers to the same question, so question difficulty alone cannot explain it. Only questions with both correct and wrong answers inform it. The longest decile is each configuration's top 10% of answers by output tokens, rounded up. Length is descriptive here; it has not been validated as an abstention rule. Display filters hide chart rows; the summary uses every complete configuration.

06

Go from a score to a question

Difficulty is measured on a fixed panel of configurations that completed every question in the current scope.

Configurations from the same model are correlated; panel counts are descriptive votes, not independent evidence. A review flag requires at least three complete configurations and a strict majority choosing the same non-key option. It does not modify the supplied answer key.

Do two configurations miss the same things?

Compare paired outcomes, complementary strengths, and shared failures.

Only complete configurations are offered. “Either correct” is an oracle upper bound that knows the key; it is not the accuracy of a deployable ensemble. Comparisons are exploratory, with no multiple-comparison significance claims.

Serving provider

OpenRouter can route one model to different providers over a run. This table lists models served by more than one provider in the scope. Expected accuracy is the complete-panel accuracy on the same questions, excluding every configuration of the same model. Routing changes over time, so providers often serve different question blocks; this adjustment addresses that. It does not adjust for tier mix, so compare the tiers served. The last column compares the provider with the model's other providers pooled; its interval clusters answers by question and needs at least 10 answers on each side. Rows are exploratory, with no multiple-comparison correction.

09

Method & provenance

Enough context to reproduce the scores and interpret their limits.

Scoring protocol

Four options, one supplied key. Each question has equal weight. Incorrect, invalid, refused, and truncated completions count as wrong. Unresolved requests leave a configuration unranked. Skipping image questions never shrinks the full-exam denominator.

The benchmark requests a strict JSON answer, with original question text and image bytes. It supplies no grading metadata or answer key. Sampling uses provider defaults; no client token cap is set. No research tools or automatic resampling are used.

Comparison limits

OpenRouter and Claude Code are distinct protocols. Claude can use internal turns to produce structured output. Requested effort can be mapped or clamped by the provider. Reported API-price estimates for subscription usage are not charges and never enter cost rankings.

The supplied key is the grading reference, not an independently verified official key. This report cannot determine training contamination, repeatability, or generalization beyond the selected exam.

Source runs & inference origins

Selected jobs identify the run whose result was used; origin answers identify the run that performed the retained inference. They can differ because of caching. Zero timeout or budget means the corresponding local guard was disabled.
